# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **Torrent Files With Newlines in Their Names**: Some torrents name their file with an embedded newline (e.g. `Title [Group]` + newline + `.zip`). FTP is line based, so such a file can't be listed or fetched: the transfer asked for the name cut at the newline and failed with `550 No such file or directory`, then retried forever. When a torrent finishes, the download progress checker now has the torrent client (Transmission `torrent-rename-path`, qBittorrent `renameFile`/`renameFolder`) rename every file and folder whose name has control characters before transferring it (`TorrentClient.clean_file_names()`), so the file on the seedbox is fixed too. FTP listings detect the split lines, drop the broken entry and log a warning naming the folder, instead of failing with a vague not-found. `replace_illegal_name()` also strips control characters, so local archive names built from torrent names stay clean.

## [1.5.0] - 2026-11-21

### Added

- **Versioned JSON API (`/api/v1/`)**: The command API is now served at `/api/v1/` (`/api/v1/?archive=5`), with the same commands as `/api/` and `/jsearch/`. `GET /api/v1/` without parameters links to the docs. The remote operations API (formerly only `/admin-api/` and `/jsonapi/`) is at `/api/v1/remote/`.
- **Task Status for API Clients (`GET ?task=<id>`, `GET ?tasks=<id1>,<id2>`)**: Returns a background task's status, Unix timestamps (created, started, finished, delayed until), attempts, error message and a result summary (targets, delete options, crawl statistics). Works with a `read` scoped token. Only staff and the user who queued the task can see it. Every command that queues tasks (`DELETE ?archive=`/`?gid=`/`?gallery=`, `POST ?update-metadata=`, and the remote crawl operations) now answers with `task_id` (or `task_ids`) and a `status_url` to poll. The batch form has the same keys as `/api/tasks/status/`, and Archive Manager's JSON bulk action responses also include a `status_url`.
- **`TaskQueue.result`**: Workers save what a task did when it completes: the `UpdateSummary` counts for `gallery_updater` (requested, fetched, updated, failed, unsupported links), the pruned rows for `database_prune` and the counters of the check for `archive_file_check`. The API's task status returns it as `result.details`, and the admin shows it. Migration `workers.0007_taskqueue_result`.
- **OpenAPI 3.1 Document and Interactive Docs**: `/api/v1/openapi.json` is generated from the command registry (parameters, permissions, token scopes, request bodies, error responses), and `/api/v1/docs/` serves it in Swagger UI (vendored, 5.34.1) with "Try it out" using the session or a bearer token, styled in the site's dark blue theme (Swagger UI's dark mode re-tinted by `css/api_docs.css`). A copy is committed as `docs/api/openapi.json` (rendered by GitLab's file viewer); `manage.py openapi_schema` exports it (`--output`, `--server`) and regenerates (`--update`) or checks (`--check`) the committed copy, and a test fails while it is out of date.
- **Reader Commands**: The `/r-api/` endpoints from `viewer/views/exp.py` are now commands of the API: `archive-reader`, `archive-images`, `archives-browse`, `archives-quick`, `archives-simple`, `me`, `POST extract-archive` and `POST reduce-archive`.
- **Live Task Tracking on Gallery Page, `/tools/`, and Archive Manager**:
  - `gallery_new.html`: Recall API, Default/Force Download, and Refetch Thumbnail (now queued as a `gallery_thumbnail_worker` background task instead of blocking the request thread) send HTMX requests and show live polling status badges in the Tools bar, including active tasks on page load.
  - `/tools/`: All background-queued maintenance tools (thumbnail generation, file info recalculation, publish hidden, wanted gallery search/matching, retry failed, update newer than / missing thumbnails, internal archive matching) now use HTMX task polling with full-width list-group status rows and reflect active tasks on page load.
  - Archive Manager bulk actions (`delete_files_archives`, `update_metadata`, `extract_contextual_info`): return queued `task_ids` and poll `/api/tasks/status/?ids=...` with a live progress toast and queue-panel progress bar, refreshing the listing as tasks finish instead of relying on hardcoded 3s/10s timers.
- **Expired Session Pruning (`retention.session_days`)**: Added chunked `django_session` pruning to the retention service, `TimedDatabasePruner`, and `manage.py prune_db --session-days`.
- **Configurable Database Log Level (`general.sql_log_level`)**: Added `general.sql_log_level` (default `INFO`) to configure the `StatusLog` database handler level independently of rotating file logs.

### Changed

- **Elasticsearch Search & Facet Performance**: Reduced per-request ES roundtrips from 3 to 1, replaced sidebar facet links with JS-driven buttons, optimized facet building and date parsing, added view-aware `_source` filtering, and skipped aggregations on `no_agg` / `recall_api`.
- **Anonymous Session Handling**: Stopped creating or writing `django_session` entries on anonymous and stateless `GET` requests across archive search, gallery list, ES search, and session settings views (anonymous `view` mode switches are stored in lightweight cookies with `rel="nofollow"` on view-toggle links).
- **Worker & Scheduler Database Write Reduction**: Batched `WorkerProcess` and `SchedulerState` heartbeat sync into a single transaction, removed per-scheduler `SELECT`s, added idle backoff with wake-on-enqueue to `archive_download_queue`, skipped idle `last_run` DB writes, and skipped auto-starting `archive_download_queue` when queuing is disabled.
- **ORM Query, Task Serialization & Index Optimizations**: Switched `/search/` and `/galleries/` tag filtering to `EXISTS` / `NOT EXISTS` semi-joins, removed unnecessary HTML tag prefetches, deferred `provider_metadata`, streamed `gen-ddl` PKs, aligned `/feed/` ordering with `NULLS LAST`, added diff-only `TaskQueue.options` serialization, added partial `TaskQueue` active/finished indexes (migrations `workers.0008`, `workers.0009`) and combined 24h dashboard counts, and removed strictly superseded indexes (migration `viewer.0229`).
- **One API Error Format**: All API errors (`/api/v1/`, `/api/`, `/jsearch/`, `/r-api/`, `/admin-api/`) use `{"error": {"code": "...", "message": "..."}}` with a proper HTTP status: `400` for unknown commands (was `200`, or `404` for `DELETE`), invalid IDs (was `200`), invalid JSON and missing body fields (was `500`); `401` with `WWW-Authenticate` for missing authentication (was `403`); `403` for missing permissions; `405` with `Allow`; `415` for form-encoded bodies; a JSON `500` instead of an HTML page. Legacy routes keep the keys their clients read: `result` on `/api/` and `/jsearch/`, `result: "error"` plus `message` on `/r-api/`, `message` on `/admin-api/`. Successful responses are unchanged.
- **One Authentication Path**: Every API surface uses the same session-or-bearer-token check with `read`/`write`/`remote` scopes. On `/api/v1/` a bad or expired token is a `401` (`invalid_token`) and a token without the scope a `403` (`insufficient_scope`), instead of silently being treated as anonymous (the legacy routes keep the old behavior). Tokens of disabled users are no longer accepted.
- **`viewer/views/exp.py` Merged into `viewer/views/api/`**: `/r-api/` is now a deprecated shim over the reader commands; its responses have `Deprecation: true` and `Link: <...>; rel="successor-version"` headers. `/admin-api/` and `/jsonapi/` are deprecated aliases of `/api/v1/remote/` with the same headers. `/api/` and `/jsearch/` stay supported. The userscript (0.2.04) and the admin match/crawl buttons now call `/api/v1/remote/` and show error messages.
- **Single Inline Archive Edit Form**: The staff-only edit page (`/archive/<id>/edit/`) is merged into the archive page's inline "Edit" form, on both the new and old archive pages. Users with `change_archive` see the same fields as before. Staff also get the fields that were only on the edit page: possible matches (picking one sets it as the main gallery and clears the candidates), custom tags, archive groups and the file name (renames the file; a name that already exists is rejected). The match tools (Generate matches, Match, Clear possible matches) are in the form's header. Saving redirects back to the page and logs one change-log entry. Custom tags are only added or removed when they differ, so an unchanged set doesn't log a change, and blank text fields keep their stored empty value. The old `/edit/` URLs redirect to the page with the form open.
- **Drag and Drop Image Editor**: The staff image position/delete formset is now an image editor in the edit form. A button loads it on demand (HTMX), so a normal page load doesn't query the image set for it. All the images are in one grid, without pagination. Drag a thumbnail to move it, type a position to send it there, sort by file name (natural sort), reverse, mark images for deletion, or reset. Save sends the new order. If the archive's images changed after the editor loaded, nothing is saved. Deleting images asks for confirmation first.

### Removed

- **`remotesite` Command and Its Remote Operations**: The `manage.py remotesite` command (instance-to-instance sync over the remote API and FTPS) is removed, together with the remote API operations only it used: `archive_request`, `force_queue_archives`, `queue_archives`, `queue_galleries` and `links` now answer `400` (`unknown_command`), and the body-level `archive_reason` / `archive_details` fields are gone. `webcrawler`, `match_archive`, `match_archive_internally` and `GET ?gc=` are unchanged. The `remote_site` config section is removed too (a leftover section in `settings.yaml` is ignored).

### Fixed

- **ES Search Facet Sidebar Covering Top-Nav Menus**: On `/es-index/` and `/es-gallery-index/`, the fixed facet sidebar shared Bootstrap's dropdown `z-index` (1000) and was drawn over the top-nav dropdowns and quick-search autocomplete. It now sits just below that layer (`css/dashboard.css`).
- **Torrent Transfers Blocked by Extra Files**: A finished torrent whose folder had an archive next to an uploader's note (e.g. `Thanks for UPload.txt` beside the `.zip`) was reported as ambiguous and retried forever. Only accepted files (supported archives and images) and subfolders are now considered when finding a torrent's download. Other files are ignored (logged at debug level) and are no longer added when loose images are zipped.
- **`retention` Section Missing from the Config Template**: `manage.py config_schema --update-default` regenerated `default.yaml` without the `retention` section, which had only been added to `default.yaml`. The template in `core/base/config_models.py` now has it, and a test fails when `default.yaml` and the template differ.
- **Stable Button Width Across Task Status Stages**: Background task action buttons (`js/task_actions.js` + `task_status.html`) lock their width from initial click through `queued`, `running`, and `completed`/`failed` stages (with clean ellipsis and full details on hover, plus a non-shifting toolbar footer notice when no worker is running) so neighboring buttons never shift and cause misclicks.
- **`Gallery.match_against_wanted_galleries()` Full-Table Scan on Empty Queryset**: Fixed an empty `wanted_filters` queryset falling back to `WantedGallery.objects.all()`, skipped rematching in `sync_gallery_db_entry()` when a gallery has no `FoundGallery` links, and eliminated repeated tag queries inside the match loop.
- **Control & Stale Entries in Workers Dashboard (`worker_runner`, `post_downloader`)**: Tagged internal worker IPC control rows (`worker_runner`, `worker_process`) with `schedule_type="control"` and excluded them from the workers dashboard, admin report, `SchedulerState.get_all_statuses()`, and `WorkerContext.get_active_initialized_workers_from_db()`. Added migration `workers.0009_cleanup_control_and_stale_scheduler_states` to reclassify existing control rows and delete leftover `post_downloader`/`timed_downloader` rows, automatic stale-row pruning on worker startup, and a `404` guard in `/api/workers/action/` so unknown or control names cannot create phantom `SchedulerState` rows.

### Security

- **POST-Only State-Changing Views**: Enforced CSRF-protected `POST` (returning `405 Method Not Allowed` on `GET`) across all remaining state-changing web views: `/web-queue/<op>/<args>/`, archive tools (`/archive/<id>/extract/`, `/reduce/`, `/check-convert-type/`, `/mark-similar-archives/`, `/generate-matches/`, `/update/<id>/...`), collaborator match updates (`/col-update/<id>/...`, `/col-gallery-update/<id>/...`), gallery tool routes (`/gallery/<id>/<tool>/`, `/gallery-find/<tool>/`), wanted gallery tools (`/wanted-gallery/<id>/` with `tool`), archive group `extract_all`, `/user-archive-preferences/<id>/<setting>/`, and `/logout/`. Updated all corresponding templates, HTMX triggers, and inline AJAX calls to send `POST` with CSRF tokens.

## [1.4.0] - 2026-11-20

### Added

- **Wanted Gallery Admin Actions**: "Add wanted tags" and "Remove wanted tags" actions on `/admin/viewer/wantedgallery/`, taking a comma separated list of tags (`scope:name` or `name`) in the action's text field. Adding creates missing tags; removing skips (and reports) tags that don't exist.
- **Archive Manager Recycle Info and Mark Reasons**: The expanded view of `/archive-manager/` now shows each mark's reason, along with "In Recycle bin?", "Recycle reason, user, date" (for binned archives) and "Is file deleted?". The JSON listing (`?json=1`) gains `binned`, `file_deleted` and `recycle_entry` (`reason`, `user`, `comment`, `date`, `origin`) for each archive; `recycle_entry` is only filled for users with `recycle_archive`.
- **Archive Manager "Delete files only" Action**: New bulk action next to the delete button, matching the single archive page's "Delete associated file (preserves metadata...)" option: it deletes only the archive files, keeps the archive entries and their image data, marks them as file deleted and moves them to the Recycle Bin. It runs in the background (one `delete_archive_worker` task per archive), needs `delete_archive`, and uses the same gallery options as the full delete (mark deleted, deny or delete). The existing button is now labeled "Delete archives and files", and the danger zone explains both.
- **Archive Manager Three-Way Recycled / File Deleted Filters**: The "Recycled (only)" and "File Deleted (only)" checkboxes are now selects with "No" (the default, hides those archives), "Yes (only)" and "Any" (ignores the filter), so you can, for example, list recycled archives whose file was or wasn't deleted, or every archive regardless of either. The `recycled` and `file_deleted` parameters take `1` (only), `any` (ignore) or `0`/absent (hide); existing `=1` links work as before. Also used by bulk actions with "Run for all" and accepted by the archive picker API.
- **Archive Manager Navigation and Refresh**: The pagination bar (page, total, selected count, page size) is now also shown above the results, with a Refresh button on both bars. After an action finishes the list reloads and deselects the archives that are no longer listed (e.g. recycled, deleted, or published while showing private archives). Actions that run in the background ("Delete files only", "Update metadata") reload the list again after 3 and 10 seconds.
- **New Archive and Gallery Pages as Default**: New `urls.new_detail_views_as_default` setting (default `false`). When `true`, `/archive/<id>/` and `/gallery/<id>/` show the new detail pages and the old ones are at `/archive_old/<id>/` and `/gallery_old/<id>/`. When `false`, `/archive/` and `/gallery/` keep showing the old pages and the new ones are at `/archive_new/<id>/` and `/gallery_new/<id>/`. Both `_new` and `_old` routes always exist. The setting is read once at startup, so changing it needs a restart.
- **Background Tool Buttons Follow Their Task**: On the new archive page, the buttons that queue a worker task (Expand, Expand (resized), Reduce, Recalc, Extract Context, Mark similar, Recall API, Calc SHA1, Set Public, Convert zip, Rematch) no longer reload the page. They send the request through HTMX, turn into the task's status ("queued (N ahead)", "running...", "No worker running" when no worker sends a heartbeat) and poll `/api/tasks/<id>/status/` until the task ends. The page then reloads by itself, unless you've started typing in one of its forms; a failed task shows its error on hover. A task that's still running when you open the page shows its status too. Requests without HTMX work as before. Any action view can use it through `viewer.utils.task_actions.task_action_response()`, and templates show a task's status with `{% task_status task %}`.
- **Archive Manager "Gallery has other archives" Filter**: New filter next to "Different filesize" that lists archives whose gallery has at least one other archive outside the Recycle Bin (`gallery-other-archives=1`), to find duplicates. Also accepted by the archive picker API.
- **Archive Manager "Favorite" Filter**: Lists the archives you marked as favorite (`only_favorites=1`), like the "Favorite" filter on the archive search page. Also applies to "Run for all".
- **Archive Manager "Extract Context" Action**: Bulk "Extract Context" with a profile picker (defaults to `manga_extractor.default_profile`), queuing one contextual extraction per archive. Like on the archive page, it only appears when `manga_extractor.enable` is on and the user is staff or has `extract_contextual_info`. The JSON listing gains a `manga_extractor` object (`enabled`, `profiles`, `default_profile`), and `permissions.extract_contextual_info` now also counts staff. Sending the action while the extractor is disabled returns an error instead of doing nothing.
- **Public API Gallery Status, Archive Deletion, and Metadata Update**: Added authenticated write endpoints (`write` scope for bearer tokens) to `/api/` supporting provider `gid` (and internal IDs):
  - `PUT /api/?gid=<gid>[&provider=<p>]` and `PUT /api/?gallery=<id>` to change gallery status to `deleted`, `denied`, or `normal` with optional `reason` (requires `mark_delete_gallery` for `deleted`/`normal`, `approve_gallery` for `denied`).
  - `DELETE /api/?gid=<gid>[&provider=<p>]`, `DELETE /api/?gallery=<id>`, and `DELETE /api/?archive=<id>` to queue `delete_archive_worker` deletions with `delete_archive`, `delete_file`, `delete_zipped` (recycle bin), `mark_gallery_deleted`, `mark_gallery_denied`, `delete_gallery`, `archive_ids`, and `reason` options via JSON body or query parameters (requires `delete_archive`, plus the corresponding gallery permissions when gallery flags are set).
  - `POST /api/?update-metadata=` taking `gid`, `gids`, `gallery`, or `archive` (plus optional `provider` and `reason`) to enqueue a `gallery_updater` metadata refresh (requires `update_metadata`).

### Changed

- **Grouped Logs for Split Web Crawler Batches**: When `/web-crawler/` splits links into multiple tasks via "Split into groups", the queued tasks now share a batch ID, demote repetitive per-block database/metadata/dispatch summaries to `DEBUG`, and emit one aggregated `INFO` summary across all blocks in the submission once the last block finishes (including when remaining pending blocks are cancelled or cleared, without firing early on provider ban delays).
- **Archive and Gallery Page Style**: The `?view_style=new` parameter no longer selects the new archive and gallery pages; use `/archive_new/<id>/` and `/gallery_new/<id>/`, or turn on `urls.new_detail_views_as_default`.
- **Gallery and Archive Change Log**: Replaced `django-simple-history` (now removed) with a change log that stores only what changed: the tracked fields' old and new values, and the tags added or removed. Saves and provider refreshes that change nothing no longer write anything, and a refresh that changes fields and tags writes one entry instead of up to three full snapshots with a copy of every tag. Tracked gallery fields: title, title_jpn, category, uploader, comment, expunged, disowned, rating, fjord, public and tags. Tracked archive fields: title, title_jpn, source_type, reason, public_date, public, gallery, details and custom tags (tags copied from the gallery are already in the gallery's log). Fields that don't change upstream or are already covered by the activity log (e.g. posted, file count/size, status, crc32, binned) and `provider_metadata` are no longer kept in the history. The change log pages list the changes directly; the "Show object data" toggle is gone.
  - Migrations `0225`–`0228` convert the existing history, then drop the `viewer_historicalgallery`, `viewer_historicalgallery_tags` and `viewer_historicalarchive` tables. Identical consecutive snapshots are discarded and snapshots taken within 5 seconds of each other are merged. History of deleted galleries/archives and of deleted tags is not kept. On large tables the conversion can take a while; it prints its progress.
  - `history_days` retention now prunes change log rows by date. It no longer needs to keep the newest snapshot of each object, since the current values live in the gallery or archive itself.
- **Streamlined Submit Queue, Archive Matching, Activity Event Log, Downloads and Server Logs pages**: The five pages now share the look of the database maintenance, workers and file check pages (shared `css/dm-pages.css` / `js/dm-pages.js`): clickable summary tiles that act as quick filters (pending/approved/denied entries, unmatched archives and archives with candidates, queued/running/finished/failed downloads, errors/warnings in the last 24 hours), removable chips for the active filters, a pager with page jump and page size, relative times, and a bulk action bar that follows the scroll and enables its buttons once something is selected (shift-click selects a range, clicking a row toggles it).
  - Submit queue: status filter (`status=submitted|approved|denied|already_present`, the older checkboxes still work), thumbnails, wanted/archive/similar flags, resolution details. Gallery filters apply as soon as one has a value, without "Filter galleries".
  - Archive matching: candidates grouped per gallery with accuracy bars and image count/size comparison; "Link" and "Clear" work without reloading the page; matching worker status; provider, method, cutoff and auto-link in the action bar.
  - Activity event log: top actions and users of the last 7 days as quick filters, searchable action picker, user filter (`user=`, staff or `read_all_logs`), "all events of this object" links, expandable data. Title/tags search both galleries and archives when neither is chosen.
  - Downloads and server logs: live refresh with a Live/Paused toggle (downloads are live by default), selection kept across refreshes on downloads, collapsible tracebacks and a logger filter link on logs.
  - Bulk actions on the submit queue and archive matching redirect after posting, so reloading doesn't repeat them.

### Fixed

- **Archive Manager "Run for all"**: Bulk actions with "Run for all" now use the same filters as the listing. Before, they ignored several filters (different filesize, custom/scopeless tags, extra files, gallery in queue), so they could act on archives that weren't listed.
- **Missing Referer Errors**: Views that redirect back to the previous page no longer fail with a server error when the browser sends no `Referer` header (privacy settings, `Referrer-Policy: no-referrer`). They go to a sensible page instead (the archive, gallery, tools or list page), and a `Referer` pointing to another site is ignored.
- **Download Monitor and Server Logs Escaping**: Rows added by the auto-refresh now escape download names, error messages and log messages instead of inserting them as HTML.
- **Event Log and Submit Queue Date Filters**: The "to" date now includes the whole day.
- **wanimagazine Wanted Generator**: Fixed the wanimagazine parser after changes on the remote site. Feed subpaths in `wanted_params_<n>_subpath` may need to be updated.
- **Collaborator View Permissions**: Restored permission checks lost when the collaborator views were split into modules. `/match-archives/` requires `match_archive` again and `/archives-by-field/` requires `manage_archive` again. `/upload-archive/` no longer also needs `match_archive`, and `/galleries-by-field/` no longer also needs `manage_archive`.
- **Web Crawler Per-Gallery Log Counter**: `"Working with gallery X of Y"` no longer stops after 50 galleries when fast bulk mode (`silent_processing`) is disabled; milestone-only logging is now used only in silent processing mode.

### Security

- **Archive Manager Marks**: The archive manager JSON listing no longer returns marks to users without `view_marks`, and no longer includes `Not Indexed` marks, matching the HTML page. It also no longer runs an extra marks query for every archive.
- **Monitored Link Permissions**: Changing monitored links now needs Django's model permissions on top of `view_monitored_links`: `add_monitoredlink` to create, `change_monitoredlink` to edit, start, stop or force-run, and `delete_monitoredlink` to delete. Users who only have `view_monitored_links` can still see the list but no longer change links; give the other permissions to users or groups that should. Start, stop, force-run and the inline actions on `/monitored-links/` now only work with POST, and the list only shows the buttons the user can use.

## [1.3.0] - 2026-11-14

### Added

- **Admin Report**: New staff page at `/admin-report/` (Settings → Admin Report) summarizing a time window (last 24 hours, 7 or 30 days, or a custom range): archives and galleries added, event log activity, wanted gallery matches, finished and failed downloads, failed tasks, warning/error server logs grouped by similar message, submissions, and new archive file-check issues. It also shows the current state: download and task backlogs, unresponsive or overdue schedulers, stale worker processes, provider rate-limit cooldowns, disk usage of the media folders, and a "Needs attention" summary. Sections, minimum log level and list sizes are selectable. `?format=json` returns the same data, for staff sessions or bearer tokens with the `read` scope (see `docs/api/admin_report.md`).
- **Scheduled Admin Report Emails**: Each staff user can have the admin report emailed on their own schedule ("My report email" on the admin report page): every N hours, daily or weekly at a time in their own time zone, with their choice of sections, minimum log level and list size, and an option to skip the email when nothing needs attention. Each email covers the time since that user's last report, and links to the same report on the site; the page also gets a "Since my last report email" window and a "Send my report now" button. Sent by the new `timed_admin_reporter` scheduler, enabled with `admin_report.enable` (checks every `admin_report.check_interval_minutes`, default 15) and using the `mail_logging` SMTP settings. Adds the `AdminReportSubscription` model (migration `0224`).
- **SFTP Post-Download Transfers**: The `remote` download handler can now fetch finished torrent and H@H downloads over SFTP as well as FTPS. Set `protocol: sftp` in the `ftps` section or in a named `ftp_configs` entry (selected with `download_ftp_torrent` / `download_ftp_hath`). SFTP supports password or key authentication (`key_filename`, `key_passphrase`, falling back to the SSH agent and `~/.ssh` keys when neither is set), host key checks against `~/.ssh/known_hosts` plus an optional `known_hosts_file` (`no_certificate_check: true` accepts any host key), `port` (default 22), `bind_host` / `bind_port`, transfer progress reporting, and reconnect-and-retry on dropped connections. Adds the `paramiko` dependency.

### Changed

- **Settings Backed by the Config Models**: `Settings` attributes (`wait_timer`, `replace_metadata`, `MEDIA_ROOT`, ...) now read and write their Pydantic config section model instead of keeping a copy, so assignments are validated, and `settings.database` / `torrent` / `ftps` / `remote_site` are the section models (dict-style access still works). A `Settings` built without a config, or from a config missing a whole section, now uses the model defaults for that section (e.g. `convert_others_to_zip: true`, `archive_dl_folder: galleries/archive_dls`). Serialized task options no longer include the section models, which carried credentials such as `django_secret_key`; options queued by older versions still load.

### Fixed

- **Torrent Download Transfers**: Finished torrents are now found from the contents of their `<download dir>/<gid>` folder instead of a match on the expected torrent name, which could differ from the real name (e.g. the e-hentai API torrent name) and left finished downloads retrying forever. A single archive is transferred, a single subfolder (the torrent root) is followed into, and loose files are zipped; partially written files (`.!qB`, `.part`, `.incomplete`) are reported as incomplete, and ambiguous contents (several subfolders or archives) are logged and skipped. `.cbr` / `.cb7` files are now converted to zip like `.rar` / `.7z`.
- **Banned Tags & Uploaders Defaults**: A `general` section without `banned_tags` (`discard_tags`), `banned_uploaders` or `banned_search_queries` no longer bans the sample languages, the `random_guy` uploader and the sample query; these default to empty lists again, as before the move to Pydantic config models.
- **Settings Page Redaction**: The torrent client password (`pass`) is now redacted on the settings stats page.

## [1.2.0] - 2026-11-13

### Added

- **Background Archive File Checks & Picker Widgets**: Replaced the synchronous `/archive-not-present/` view (which now redirects to `/archive-file-check/`) with a background `archive_file_check` worker job.
  - Supports checking all archives, media subfolders, explicit archive IDs/ranges, or filtered archive selections with live progress polling, cancellation, re-runs, and bulk/single issue actions (re-check, recalculate file info, queue download, clear CRC32, mark deleted, delete, dismiss).
  - Added optional ZIP integrity verification when a CRC32 mismatch occurs (enabled by default with CRC32 checks) to distinguish intact ZIPs with stale checksums from corrupted or unreadable archives, with issue filtering by test result.
  - Integrated the `admin-widgets` archive and media folder pickers along with `/api/archive-picker/` and JSON autocomplete endpoints for source, reason, provider, category, and mark reason.
- **Manga Image Contextual Extraction**: Integrated `manga-extractor` for archive and image contextual extraction, supporting configurable profiles, `ocr_space_threshold`, ordered `bubble_transcripts` dialogue lists, bearer `auth_token` configuration (with environment variable fallbacks), and background worker execution.
- **Scoped API Tokens & Expiry Management**: Added `read`, `write`, and `remote` scopes, optional expiration (`expire_date` nullable for non-expiring tokens), throttled `last_used_date` tracking, and per-user unique token names on `UserLongLivedToken`, exposed in the user profile UI, Django admin, and `user-management` CLI (`--token-expiry-days`, `--token-scopes`).
- **Separate Capture & Processing Frequencies for Monitored Links**: Added an opt-in `separate_frequencies` mode with `capture_frequency` on `MonitoredLink` (and `--capture-links-only` / `--skip-link-capture` crawler flags), allowing Panda link capture to queue pending `ProcessedLinks` with status/retry tracking separately from metadata processing and downloads.
- **Background Queues for Archive Operations & Gallery Processing**:
  - Dispatched single-item archive operations (`recalc`, `clone`, `split`, `convert`, `reduce`, `sha1`, `similar`, `matches`, `delete`) to `ArchiveWorker` background tasks so web requests do not time out.
  - Added dedicated `gallery_creator` and `gallery_updater` worker task queues to decouple gallery creation and metadata refreshes (`GalleryMetadataUpdater`) from the web crawler pipeline.
- **Web Crawler Bulk Input & UI Controls**: Added text file upload (`multipart/form-data`), link-group splitting (`split into groups` persisted in local storage), and a `Fast bulk mode (silent processing)` option to `/web-crawler/`, along with standardized summary logging for database checks, metadata evaluations, and discarded gallery counts across providers.
- **Provider Ban Cooldowns**: Added persistent temporary IP ban detection and dynamic cooldown tracking (`ProviderRateLimit.cooldown_until`) for Panda, pausing requests during cooldowns and raising `ProviderBannedError` so worker tasks re-queue with `not_before` without burning attempts.

### Changed

- **Unified Matching Engine & Shared Provider Rate Limiting**: Rebuilt online and offline archive matching (`core/matching`) on the shared provider rate limiter (`<provider>_web` buckets via `request_by_provider`) with deduplicated per-archive requests, `crc32` offline matching, `auto_link` support across views/API/workers, `--match-mode online|offline` in `foldercrawlerrun.py`, and shared rate-limited requests for parsers and wanted generators.
- **Consolidated Download Progress & Post-Download Pipeline**: Merged `TimedPostDownloader` into `DownloadProgressChecker` using a unified `TransferSource` abstraction (local folder / FTPS), running transfers in a bounded background pool (`parallel_post_downloaders`) with delayed retries, storing Transmission info hashes instead of session-scoped numeric IDs, and preventing finished torrents awaiting transfer from being purged by lifespan checks.
- **Database Indexes & ORM Query Optimization**:
  - Added PostgreSQL composite and single-column indexes on `Archive`, `ArchiveTag`, `Gallery`, and `Tag` for search and feed filtering.
  - Optimized search, archive/gallery detail views, `LatestArchivesFeed`, and bulk URL ingestion (`select_related` / `prefetch_related` / deferred text columns, SQL aggregation, avoiding unnecessary `distinct()` on negative-only tag filters, memoized `HistoricalRecords` `prev_record` lookups, and summarized logging for batches > 50 URLs).
- **Viewer UI & Tools Cleanup**:
  - Removed the redundant info badges row from archive and gallery headers.
  - Cleaned up `/tools/` by removing overlapping scheduler/worker controls already present on `/stats/workers/`, removing `-tmd` / "Transfer missing downloads", and changing "Restart Viewer" to "Restart Web Server" (`SIGHUP` to Gunicorn master).
- **Internal Architecture, Tooling & CI**:
  - Removed `Settings.set_models` and migrated `core/`, `workers/`, and `viewer/` to direct `viewer.models` imports.
  - Enabled mypy `possibly-undefined` and Ruff `F401` unused-import checks; fixed test state leaks in worker and parser tests; removed Python 3.13 from the GitLab CI test matrix.

### Fixed

- **Archive File Check & CRC32 Consistency**:
  - Compared against uncompressed image size inside the ZIP rather than file size on disk when checking archive file sizes.
  - Normalized all stored `Archive.crc32` values to 8-digit uppercase hex (`%08X`) via data migration, `pre_save` signal, and API filter normalization, and compared CRC32 values numerically so legacy unpadded values do not trigger false mismatches or missed matches.
  - Added `dirs_only=1` support and fixed directory prefix boundary checks in `/dir-browser/`.
- **Download & Worker Queue Reliability**:
  - Prevented stalled download threads from corrupting re-queued attempts by using per-attempt `.part` filenames and claim-guarded database/bookkeeping writes.
  - Separated post-download processing from file transfer so post-processing failures do not re-download already transferred archives, and verified downloaded archive sizes against `Content-Length`.
  - Preserved streaming responses and restricted ban-page body inspection in `request_by_provider` to text-like responses so binary downloads are not decoded in full.
  - Serialized `ArchiveDownloadQueue.process_queue()` with a lock and prevented unreachable torrent clients from being mistaken for removed torrents.
  - Prevented duplicate gallery downloads and duplicate update work via task deduplication, atomic per-task-type worker exclusivity (`pg_advisory_xact_lock`), and `gallery_creator` re-validation; preserved `ChaikaGalleryData` fields across `gallery_creator` handover.
  - Added `TaskQueue.attempts` / `max_attempts` so crash-interrupted tasks stop re-queueing after exhausting retries (without counting clean shutdown reverts), ensured timed-out tasks receive cancel events and stop via `TaskCancelledError`, and raised explicit errors on missing parsers, unknown task types, and empty archive task selections (requiring explicit `{"all": true}` for library-wide `fileinfo`/`thumbnails` runs).
  - Kept `GalleryMetadataUpdater` processing remaining chunks when one chunk fails, stopped refreshes from forcing `public=True`, fixed `TimedDatabasePruner.job()` busy-looping when retention is disabled, preserved the newest `django-simple-history` revision per object during pruning, and logged errors/PID collisions in `WorkerProcess.cleanup_dead_workers()`.
- **Viewer, Matcher & Deprecation Fixes**:
  - Fixed `has_positive_tag_filter` unbound error in `filter_galleries`, percent-encoded `X-Accel-Redirect` paths in `archive_thumb`, fixed `user-management -dt` lookup field, fixed `nexus` `clean_title` returning empty strings, stopped `j18` matcher from mutating shared headers, handled unparseable responses in `mugimugi` matcher, and resolved `BadHeaderError` / BeautifulSoup `text=` deprecation warnings.
