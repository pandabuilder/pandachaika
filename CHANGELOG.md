## [1.6.0] - 2026-11-24

### Added

- **Provider HTTPS certificate verification (`providers.<name>.general.ssl_verify`)**: `true` (default: Python's bundled CAs, which don't include a private CA), `false` (don't verify), or the path to a CA bundle file, like the system's `/etc/ssl/certs/ca-certificates.crt`. For servers on a private CA, like a self-hosted `doujinshi_mirror`. Applies to the provider's requests (parsers, matchers, auto wanted, downloaders that use the provider's request settings) and to its galleries' thumbnail downloads.
- **doujinshi.org Mirror Provider (`doujinshi_mirror`)**: Metadata of the closed doujinshi.org (MugiMugi), from a doujinshi-browser server (JSON API over a dump of the site), like fakku a metadata-only provider (`doujinshi_mirror_info` / `doujinshi_mirror_fake` downloaders). Set its address in `providers.doujinshi_mirror.general.url`: nothing stored depends on it, gallery links (`<url>/#/book/<id>`) are built from the setting when shown, so the server can move. Thumbnails (the cover if the mirror has it, else the small one) are stored with their original image server URL (`https://img.doujinshi.org/tn/<bucket>/<id>.jpg`) and fetched from the current mirror: new provider hook `utilities.resolve_thumbnail_url`, used through `Gallery.get_thumbnail_url()` by the thumbnail download and refetch, the Elasticsearch source thumbnail and the APIs' `thumbnail_url`.
  - Links: book pages on the mirror (`#/book/<id>`, `api/v1/books/<id>`) and the old `doujinshi.org/book/<id>/` / `mugimugi.org` links. Mirror search pages (`#/books?<filters>`, `#/item/<type>/<id>`, `api/v1/books?...`) add every book they list, up to `stop_page_number` pages (default 10), and work as release series backlog search sources (`<url>/api/v1/books?match=contains&sort=released&order=desc&q=`: the backlog query's tag terms like `-language:translated$` and quotes are left out of the title search; backlog search now also asks the parser of a provider whose address is a setting).
  - Title matcher (`doujinshi_mirror_title`): the server's fuzzy title search (`/api/v1/books/match`), which reads the circle and author from `(event) [circle (author)] title` names; scored against the title without its bracketed parts.
  - Auto wanted sources with the API's book search filters (circle, author, type, publisher, release dates, ...). See `docs/AUTO_WANTED.md`.
  - Books keep the old provider's gids (`mugi-B<id>`) and tags (`artist`, `group`, `parody`, `character`, `contents`, ...; without placeholder items like "No Convention", "No Publisher" or contents "Unknown"), and books already added by mugimugi count as known in auto wanted.
- **Release Completeness (`/release-series/`)**: A Data menu page (staff only) that finds the missing issues of magazines and other periodicals: year and month (`COMIC LO 2026-12`), year and issue number (`WEEKLY Kairakuten 2026 No.42`) or issue number (`COMIC X-EROS #141`) series. Each release series (new `ReleaseSeries` and `ReleaseSeriesDismissal` models, migrations `viewer.0230_release_series` and `viewer.0231_release_series_page_query`) picks its galleries and archives by title texts, excluded texts, tags and allowed languages, reads the issue from the title with regexes (built from the name by default, combined issues like `2026-01・02` included), and compares them with a schedule of periods (`2010-01 monthly`, `2024-02 even`, `2021 48`). A gallery or an archive is enough for an issue to be found; issues found only as galleries without an archive are shown in purple on the grid ("gallery only", also in the JSON). See `docs/RELEASE_SERIES.md`.
  - Series page: a grid of the issues (found, missing, due, next, dismissed), the missing issues with their estimated release date, and the candidates whose title has no issue. It suggests a schedule from the issues found (where they become regular, monthly to even/odd months switches) and measures the lead days (how long before its cover month an issue comes out), which date the missing issues and mark the recently released ones as due instead of missing. Issues never released or combined can be dismissed.
  - Completeness counts archives: galleries are only metadata, so an issue found only as galleries doesn't make a series complete. The overview's Complete bar shows the archived share (green, yellow while incomplete) followed by the gallery-only share (purple), with the archived count and "+N gallery"; the series page's Complete tile is the archived percentage, with the gallery-only count and the percentage counting galleries under it. The JSON adds `archived`, `completeness` and `archive_completeness`.
  - Overview: every series with its completeness, and all their missing issues by release date, grouped when released close together, which shows when the crawlers weren't running.
  - Backlog search: searches the `backlog_search.urls` sources for missing issues (one, or several in turn), without adding anything: `es-gallery-json` endpoints with the series' backlog query, and panda search pages (read with the panda parser's new `links_from_search_page()` hook and the API, with the panda settings) with its backlog page query; each result shows whether it's expunged, replaced by a newer version of its gallery chain (or an update of an older one), its `other:already_uploaded`/`other:replaced` tags, its id and the sources that found it (one row per gallery); only the best candidate per issue is preselected (its title is that issue, in an allowed language, not already here, not expunged, not replaced), and "Add checked" queues them in the web crawler like Add URLs (`crawler_adder` permission).
  - The backlog search dialog opens without querying sources automatically so you can deselect sources or edit the search title for each issue (`{title}` in the backlog queries, by default the name and the issue, which the default queries now use) before clicking "Search", to find uploads titled in an unusual way.
  - Backlog results already here get a "not counted" badge when the series doesn't count them (or their archives) as the issue searched, with the reasons in its tooltip (title text, excluded text, tags, language or title regex), for issues shown as missing while their gallery is here.
  - Year and number series also read issues numbered without a year, from title regex lines without a `year` group (`WEEKLY Kairakuten Vol.37` is `#37`), for the issues before a series started counting them per year; a `#1 all` schedule line checks them before the yearly ones.
  - Export and import of the series as JSON, and `?format=json` on both pages.
- **Auto Wanted Sources (`/auto-wanted/`)**: The auto wanted queries are now set up on a page (Manage menu, staff only) instead of `wanted_params_<query>_<name>` provider attributes. Each source (new `AutoWantedSource` model, migration `viewer.0233_auto_wanted_source`) is one provider query, with a form for its provider's parameters (declared by each wanted generator's `WANTED_PARAMS`: wanimagazine, fakku, mugimugi; validated on save and import), an active flag, its own force process, and the values of the wanted galleries it creates (reason, should search, keep searching, notify when found, public, wanted providers, unwanted title). See `docs/AUTO_WANTED.md`.
  - Each source has its own frequency (Monitored Links duration format, `06:00:00`), or runs every `auto_wanted.cycle_timer` hours without one. The `auto_wanted` scheduler now wakes up when the next source is due (and at least every 15 minutes) and runs the due ones, a thread per provider, never two runs of the same provider at once; a forced run from the workers dashboard runs every active source. The list shows when each source runs next.
  - The `auto_wanted` scheduler runs the active sources (a thread per provider); "Run selected", "Run all active now" and "Save and run" queue a new `auto_wanted_worker` task. Each source shows its last run: status, errors, new links, wanted galleries and mentions added. Wanted galleries remember the source that created them (`WantedGallery.auto_wanted_source`), listed on the source's page.
  - Export and import of the sources as JSON (by name, fields left out keep their value), duplicate a source, and `?format=json` on the list.
  - The old provider attributes are no longer read: the list page imports them as sources (active when their provider is in `auto_wanted.providers`, with each generator's old defaults), shows them as JSON, and deletes them once imported. `auto_wanted.providers` is only used by that import now.
- **Auto Updater Schedules (`/auto-updater/`)**: When each provider's galleries get their metadata refreshed is now set up on a page (Manage menu, staff only), a schedule per provider (new `AutoUpdaterSchedule` model, migration `viewer.0235_auto_updater_schedule`), instead of the `autoupdater` settings. A schedule lists the gallery ages (time since posted) to update at, as rules: "from 6h to 1d every 6h", "once at 30d". Tags are added by users, mostly right after a release, so updates can now be frequent while a gallery is new and sparse after that, instead of a fixed window updated every `cycle_timer` days. See `docs/AUTO_UPDATER.md`.
  - Visual editor: a timeline of the update ages (log scale) over the changes the gallery change log recorded for the provider in the last 90 days by gallery age (tag changes and other changes), where each rule can be dragged (ends to resize, body to move), double-click to add a single update, presets ("Close to release", "Light", "First week, daily" and the old settings), and the posted date range covered, the galleries in it, the updates per day (galleries posted per day × updates per gallery) and what a run now would queue.
  - Each run queues the galleries that reached an update age since the previous run as a `gallery_updater` task, so a gallery is updated exactly once per age; `queue_every` (default 1h) only sets how often. A stopped scheduler catches up at most one day. "Run now" and "Run selected now" run a schedule like the scheduler; "Update whole range now" queues every gallery between the first and last age once.
  - A single `auto_updater` scheduler replaces the `auto_updater_<provider>` ones (their states are removed on start): it wakes when the next schedule is due, and at least every 15 minutes.
  - Export and import of the schedules as JSON (by provider), and `?format=json` on the list.
  - The `autoupdater.providers`, `cycle_timer`, `buffer_back` and `buffer_after` settings (and the providers' `autoupdater_*` overrides) are no longer read: the list page imports them as schedules (an update every `cycle_timer` days from `buffer_after` to `cycle_timer + buffer_back` days of age, the same galleries the old updater refreshed). Until they're imported or a schedule is created, nothing is updated. `autoupdater.enable` and `startup` still control the scheduler.
- **Monitored Link Details and Run Stats (`/monitored-link/<id>/`)**: Each monitored link run now records what it found and did (new `MonitoredLinkRun` model, migration `viewer.0234_monitoredlinkrun`): for the capture, the pages read, the links found split in new ones and ones already seen by an earlier run (the overlap between runs), and why it stopped (seen link, stop page, end of results, feed, no response); for the processing, the captured links taken from the queue, re-checked by the already seen window, already in the database, checked through the API, matched to wanted galleries, sent to the downloaders, and the captured links processed, left for a retry or given up on. Runs and seen links are recorded through `BaseParser` (including Panda RSS feeds in single-frequency runs and Chaika `es-gallery-json` crawls with stop-on-seen and full run stats), only for the monitored link's own URL, not for the tasks chained from it. Runs are pruned with the processed links retention (`processed_links_days`, `monitored_link_runs` entity in `prune_db`).
  - New details page, opened from the link name in `/monitored-links/` (and from the edit page): the configuration (single or separate frequencies with both intervals, effective stop on seen, already seen window, stop page, wanted galleries), the schedule (last and next capture and process runs), the seen links (pending, processed, failed, wait to be processed), 14 days of capture and processing stats (new links per day, overlap, runs with nothing new, links per page and how many a run can read before the stop page), every run with its new/seen split, and the seen links, both filterable.
  - Hints to tune the configuration: possible missed links (a capture run that only found new links and stopped at the stop page or the end of the feed before reaching the ones seen before), new links per capture interval close to what a run can read, mostly empty capture or process runs, re-reading many seen links with stop on seen off, pending links waiting for more than two process intervals, links failing to process and failed runs.
  - The list gets a "Last capture" column (new and seen links of the latest capture run, a warning when it likely missed links, and the pending links).
- **DL Type Filter on Manage Galleries**: The "More" filters have a DL Type field, with suggestions of the existing values (`gallery-dl-type-autocomplete/`, logged-in users only).
- **Add Found Galleries by Hand on Wanted Galleries**: Users who can change a wanted gallery get an "Add found galleries" button in its Found Galleries section. It opens a gallery picker: add galleries by id, range or gallery link, or search them in a window (title, provider URL or gid, tags, provider, category, uploader, images, size, posted date, without archives), prefilled with the wanted gallery's search title and flagging the galleries already found. The selected galleries become found galleries and leave the possible matches, like the Select button on a possible match. Staff can also pick deleted or denied galleries.
- **Backlog Search Falls Back to the Search Title**: When a wanted gallery has no Backlog URL query, the Backlog Search tool uses its search title instead, unless the search title is a regexp (`WantedGallery.get_backlog_url_query()`). The wanted gallery page shows the query that will be used, marked "(from search title)" when it comes from there.
- **Gallery Picker Widget and API (`/api/gallery-picker/`)**: A reusable `gallery-picker` admin widget (chaika-apps `admin-widgets`, next to the archive picker) that submits the selected gallery ids, comma separated. Its JSON API lists galleries with filters and pagination, or the galleries for `?ids=`; it's for logged-in users, and only staff see galleries that aren't Normal.
- **Archive Cold Storage**: Old archives can be offloaded to a private bucket in S3-compatible object storage (OVH Object Storage, Backblaze B2, MinIO...) to free local disk space. New `cold_storage` settings section (disabled by default; credentials also from `COLD_STORAGE_*` environment variables) and `manage.py archive_cold_storage` command: `offload` (select by id or id file, age, path prefix, size, private only; `--limit`, `--max-total-gb`, `--dry-run`), `restore`, `check` (are the offloaded files still in the bucket) and `status --verify` (checks the bucket and credentials). Offloaded archives keep a file name under `galleries/cold/`, and their downloads (`/archive/<id>/download/` and `/ext-download/`) redirect to presigned bucket URLs that expire after 6 hours, with the usual permission checks and file name. Tools that open the zip need the archive restored or the bucket mounted read-only at `MEDIA_ROOT/galleries/cold`. Deleting an offloaded archive's file deletes it from the bucket; renaming it is refused. See `docs/COLD_STORAGE.md`.
  - Archive manager (`/archive-manager/`), staff only and only while the cold storage is enabled and configured: "Offload to cold storage" and "Restore from cold storage" bulk actions (also per archive in the expanded view), queuing one `cold_storage_offload_worker` / `cold_storage_restore_worker` task per archive that needs it (others are skipped), a "Storage" filter (`storage=local|cold`, also for "Run for all" and the archive picker API) and a "Cold" badge. The JSON listing gains `cold_storage` (`enabled`: tools available for this user) and `cold_stored` for each archive. The worker tasks log `COLD_STORAGE_OFFLOAD` / `COLD_STORAGE_RESTORE` with the user and reason, and keep the task alive while large files transfer. Bulk and per-archive actions return their task ids, so the archive manager follows them like the other background actions. Includes the archive-manager bundle built from chaika-apps `71f0fa3` (`master`).

  - Stats pages: summary tiles (on collection stats, links to the matching list when you can open it), breakdown tables you can sort by any column, with share bars and a quick filter (`/`), and top tag lists with bars.
  - Tools: grouped in cards with a description and the number of items each tool would act on, worker status tiles, a tool search (`/`), and confirmations for the tools that touch every archive or restart services. Background tools still follow their task live.
  - Found galleries: tiles for the last day, week and month that filter the list, "Found by" source chips, the found gallery's thumbnail, provider and size, and the match accuracy.

The "Delete files only" action (already handled by the view) now has a button.

Per-archive searches show their answer under the archive instead of a desktop notification, and use the cutoff and max matches of the action bar. Non-matched archives gets a "Without candidates" filter and a bulk "Clear candidates" action. The batch review's table view showed no candidates before.
  - Repeated archives and different filesize archives share one layout: a card per gallery with its archives, sizes and image counts compared with the gallery, provider tiles and filter, and "Different size" / "All but one per gallery" selection helpers. A gallery with several archives of a different size is listed once.

- **Simpler Public Wanted Galleries Page**: Visitors without wanted gallery permissions only get a title search (title and Japanese title). The summary tiles, Tags, Sort, "More" filters, filter toggles and the status badges (Wanted, Searching, Keep searching, Public/Private, Restricted to links) are now only on the management version. The public list always shows public galleries that are still searched for and not found, newest release first, even when searching by title or with extra filter parameters in the URL. Anonymous visitors no longer get links to the wanted gallery pages, which need a login.
- **Local Possible Matches Options on a Wanted Gallery**: The "Possible matches locally" tool on a wanted gallery page now runs the same local title search as "Search internal" on the wanted galleries list, with the same options: provider filter, minimum cutoff (default 0.4), max possible matches (default 10) and "Must be used". It's queued as a `wanted_local_search_worker` task for that wanted gallery. The previous rule based search (title, tags, providers and categories of the wanted gallery, used by "Matches locally") is still there as "Possible matches by rules".

### Removed

- **mugimugi Provider (doujinshi.org API)**: The site is closed. Only its constants and URL resolver are left, so its galleries keep their `doujinshi.org/book/<id>/` links; its parser, matcher, downloaders, wanted generator and `providers.mugimugi` settings (`api_key`, `wanted`) are gone. Its auto wanted sources become `doujinshi_mirror` sources (migration `viewer.0236_mugimugi_auto_wanted_to_doujinshi_mirror`, parameters translated, the old ones kept in the notes; `cont`, `sub`, `FREE`, `scen` have no equivalent), and so do its old attribute queries in the legacy import.
- **"Full Metadata stats" Link**: The "Other tools" menu no longer links to `/public/stats.html`, and the unused `static_public_stats.html` template is gone.
- **Settings Objects Page (`/stats/settings/`)**: The superuser page that dumped the in-memory settings objects is removed. The Settings menu's "Configuration" entry is now "Settings file", the settings file editor (`/tools/modify_settings_editor/`).

### Fixed

- **Elasticsearch Timeout & Match-Index Cleanup**: Removed hardcoded `request_timeout=30` overrides in `remove_gallery_from_match_index`, `Archive.delete`, `Gallery.delete`, and `push-to-index` bulk calls so they respect the configured `elasticsearch.timeout`. Dropped `refresh=True` on temporary `viewer_match` deletions and caught `ConnectionTimeout` with a warning so cleanup timeouts do not abort crawls.
- **Gallery Search Reason Filter**: Fixed the advanced search panel pre-filling the `reason` filter input with the `provider` value instead of `reason`.
- **Corrupt Archive Recycling on Requeue Error**: When a downloaded archive fails ZIP, size, or SHA1 checks, errors while requeuing the download are now logged so the rest of the failure handling (recycling the archive and finishing the `DownloadEvent`) still runs instead of retrying the transfer every 5 minutes.
- **Activity Log Download Results**: Archives downloaded by the download queue logged `1` as their result and the archive download URL (H@H links included) as their data; they now log `success` and the gallery link, like the archives added directly. The thumbnail refetch logged `sucess`.
- **Archive Manager Single Task Actions Shown as Failed**: Bulk actions that queued one task (Update metadata, or a per archive action on one archive) answered with a single task `status_url` (`?task=`), while Archive Manager reads the batch summary: the progress toast showed `undefined` counts and, after the task finished, failed with `can't access property "find", e.tasks is undefined`. Responses with `task_ids` now always point to `?tasks=` (also `DELETE ?gid=` with one archive), and the archive-manager bundle (chaika-apps 8107470) reads either shape.
- **Auto Wanted Settings Docs**: `auto_wanted.cycle_timer` is in hours, not seconds as documented (it's now the frequency of the sources without their own).
- **Auto Wanted Boolean Parameters**: Text values like `False` or `0` in boolean parameters (wanimagazine `url_html_type`, fakku `link_attribute_get_text`) counted as true. The mugimugi generator failed creating a wanted gallery (`unwanted_title_regex` setting that doesn't exist).
- **Bulk Action Buttons Doing Nothing on Paged Lists**: With more than 2 pages, the pager's page-jump box was a `<form>` nested inside the page's POST form, which closed that form early and left the action bar buttons outside it (Manage Galleries, Submit Queue, Downloads, Missing Archives, Match Archives, Wanted Galleries). The page jump is now a plain input that jumps on Enter.
- **Torrent Files With Newlines in Their Names**: Some torrents name their file with an embedded newline (e.g. `Title [Group]` + newline + `.zip`). FTP is line based, so such a file can't be listed or fetched: the transfer asked for the name cut at the newline and failed with `550 No such file or directory`, then retried forever. When a torrent finishes, the download progress checker now has the torrent client (Transmission `torrent-rename-path`, qBittorrent `renameFile`/`renameFolder`) rename every file and folder whose name has control characters before transferring it (`TorrentClient.clean_file_names()`), so the file on the seedbox is fixed too. FTP listings detect the split lines, drop the broken entry and log a warning naming the folder, instead of failing with a vague not-found. `replace_illegal_name()` also strips control characters, so local archive names built from torrent names stay clean.
- **Separate Frequencies Phase Never Running After Switching Modes**: After switching a monitored link from combined to separate frequencies, the phase with the longer interval was pushed back every time the other phase ran, so it never ran (e.g. only capture ran). The phase is now anchored to the last combined run, and the anchor is stored so it survives worker restarts. Links already stuck pick it up on their next cycle; no restart is needed.

## [1.5.0] - 2026-11-21

### Added

- **Versioned JSON API (`/api/v1/`)**: The command API is now served at `/api/v1/` (`/api/v1/?archive=5`), with the same commands as `/api/` and `/jsearch/`. `GET /api/v1/` without parameters links to the docs. The remote operations API (formerly only `/admin-api/` and `/jsonapi/`) is at `/api/v1/remote/`.
- **Task Status for API Clients (`GET ?task=<id>`, `GET ?tasks=<id1>,<id2>`)**: Returns a background task's status, Unix timestamps (created, started, finished, delayed until), attempts, error message and a result summary (targets, delete options, crawl statistics). Works with a `read` scoped token. Only staff and the user who queued the task can see it. Every command that queues tasks (`DELETE ?archive=`/`?gid=`/`?gallery=`, `POST ?update-metadata=`, and the remote crawl operations) now answers with `task_id` (or `task_ids`) and a `status_url` to poll. The batch form has the same keys as `/api/tasks/status/`, and Archive Manager's JSON bulk action responses also include a `status_url`.
- **`TaskQueue.result`**: Workers save what a task did when it completes: the `UpdateSummary` counts for `gallery_updater` (requested, fetched, updated, failed, unsupported links), the pruned rows for `database_prune` and the counters of the check for `archive_file_check`. The API's task status returns it as `result.details`, and the admin shows it. Migration `workers.0007_taskqueue_result`.
- **OpenAPI 3.1 Document and Interactive Docs**: `/api/v1/openapi.json` is generated from the command registry (parameters, permissions, token scopes, request bodies, error responses), and `/api/v1/docs/` serves it in Swagger UI (vendored, 5.34.1) with "Try it out" using the session or a bearer token, styled in the site's dark blue theme (Swagger UI's dark mode re-tinted by `css/api_docs.css`). A copy is committed as `docs/api/openapi.json` (rendered by GitLab's file viewer); `manage.py openapi_schema` exports it (`--output`, `--server`) and regenerates (`--update`) or checks (`--check`) the committed copy, and a test fails while it is out of date.
- **Reader Commands**: The `/r-api/` endpoints from `viewer/views/exp.py` are now commands of the API: `archive-reader`, `archive-images`, `archives-browse`, `archives-quick`, `archives-simple`, `me`, `POST extract-archive` and `POST reduce-archive`.
- **Live Task Tracking on Gallery Page, `/tools/`, and Archive Manager**:
  - `gallery_new.html`: Recall API, Default/Force Download, and Refetch Thumbnail (now queued as a `gallery_thumbnail_worker` background task instead of blocking the request thread) send HTMX requests and show live polling status badges in the Tools bar, including active tasks on page load.
  - `/tools/`: All background-queued maintenance tools (thumbnail generation, file info recalculation, publish hidden, wanted gallery search/matching, retry failed, update newer than / missing thumbnails, internal archive matching) now use HTMX task polling with full-width list-group status rows and reflect active tasks on page load.
  - Archive Manager bulk actions (`delete_files_archives`, `update_metadata`, `extract_contextual_info`): return queued `task_ids` and poll `/api/tasks/status/?ids=...` with a live progress toast and queue-panel progress bar, refreshing the listing as tasks finish instead of relying on hardcoded 3s/10s timers.
- **Expired Session Pruning (`retention.session_days`)**: Added chunked `django_session` pruning to the retention service, `TimedDatabasePruner`, and `manage.py prune_db --session-days`.
- **Configurable Database Log Level (`general.sql_log_level`)**: Added `general.sql_log_level` (default `INFO`) to configure the `StatusLog` database handler level independently of rotating file logs.

### Changed

- **Elasticsearch Search & Facet Performance**: Reduced per-request ES roundtrips from 3 to 1, replaced sidebar facet links with JS-driven buttons, optimized facet building and date parsing, added view-aware `_source` filtering, and skipped aggregations on `no_agg` / `recall_api`.
- **Anonymous Session Handling**: Stopped creating or writing `django_session` entries on anonymous and stateless `GET` requests across archive search, gallery list, ES search, and session settings views (anonymous `view` mode switches are stored in lightweight cookies with `rel="nofollow"` on view-toggle links).
- **Worker & Scheduler Database Write Reduction**: Batched `WorkerProcess` and `SchedulerState` heartbeat sync into a single transaction, removed per-scheduler `SELECT`s, added idle backoff with wake-on-enqueue to `archive_download_queue`, skipped idle `last_run` DB writes, and skipped auto-starting `archive_download_queue` when queuing is disabled.
- **ORM Query, Task Serialization & Index Optimizations**: Switched `/search/` and `/galleries/` tag filtering to `EXISTS` / `NOT EXISTS` semi-joins, removed unnecessary HTML tag prefetches, deferred `provider_metadata`, streamed `gen-ddl` PKs, aligned `/feed/` ordering with `NULLS LAST`, added diff-only `TaskQueue.options` serialization, added partial `TaskQueue` active/finished indexes (migrations `workers.0008`, `workers.0009`) and combined 24h dashboard counts, and removed strictly superseded indexes (migration `viewer.0229`).
- **One API Error Format**: All API errors (`/api/v1/`, `/api/`, `/jsearch/`, `/r-api/`, `/admin-api/`) use `{"error": {"code": "...", "message": "..."}}` with a proper HTTP status: `400` for unknown commands (was `200`, or `404` for `DELETE`), invalid IDs (was `200`), invalid JSON and missing body fields (was `500`); `401` with `WWW-Authenticate` for missing authentication (was `403`); `403` for missing permissions; `405` with `Allow`; `415` for form-encoded bodies; a JSON `500` instead of an HTML page.
